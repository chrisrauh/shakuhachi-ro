## Score Notation Formats

Every score is saved as JSON. In the editor's source view, you can show a score as JSON, MusicXML or ABC, and edit it in any of the three. To bring in a score, paste it in MusicXML or ABC. When you save, it becomes JSON, and what JSON can't hold is not kept. The source view says what that is.

### JSON Format

Shakuhachi score notation in JSON format. Each note records what the score writes: its sign, its register, its meri or kari mark if it has one, and its duration.

**Example:**

```json
{
  "notes": [
    { "sign": "ro", "register": 0, "duration": "1" },
    { "sign": "tsu", "register": 0, "duration": "1" },
    { "sign": "re", "register": 0, "duration": "1" }
  ]
}
```

**Signs:** ro, tsu, re, chi, ri, u, hi, and others such as go-no-hi

**Accidentals:** dai-meri, meri, chu-meri, chu-kari, kari, dai-kari

**Registers:** 0 (otsu), 1 (kan), 2 (daikan)

**Duration:** the length in beats, as a string: "1" (one beat), "2" (two beats, the note and a stroke), "1/2" (half a beat, one line), "1/4" (a quarter, two lines). A half after these, as in "3/2", "5/2" or "3/4", is drawn as a dot.

### ABC Notation

Text-based music notation. A score can be just its notes:

```
D F G A d
```

Header fields such as `T:` (title) and `K:` (key) are optional. Without a key, notes read as written. With one, the key works as in standard ABC: in `K:D`, F means F♯, so it reads as re meri, and `=F` is tsu. An accidental lasts until the next bar line.

[ABC Notation Standard](https://abcnotation.com/wiki/abc:standard:v2.1)

Not kept: bar lines, the time signature, chord symbols, slurs, decorations and comments. Repeats are written out.

**Note:** Plans to add shakuhachi-specific ABC notation using Ro-Tsu-Re notation in the future.

### MusicXML Format

Standard music notation XML format.

Not kept: bar lines, time and key signatures, lyrics, other parts and layout.

[MusicXML Documentation](https://www.w3.org/2021/06/musicxml40/)
